Design for humans, AI and agents.

A practical, evidence-led design standard for digital products that need to remain useful, accessible, understandable and production-ready as software becomes increasingly AI-assisted and agent-mediated.

What v0.1 is

A working public standard built from ByJTT's existing research, Design Contracts, evidence model, Studio pipeline and AI-slop/user-pain research.

It is not a claim that every output is automatically excellent. It defines the decisions, states and evidence a serious design process should account for.

Principles

The system starts before the pixels.

Purpose, evidence, accessibility, real-world states and production reality come before decorative polish.

01

Human purpose first

Start with users, jobs, goals, constraints, risks and measurable outcomes.

02

Evidence before aesthetics

Material decisions need a user, product, platform, accessibility, brand or explicit aesthetic reason.

03

Real conditions are the design

States, content variation, devices, assistive input and failure paths are part of the product.

04

Accessible by construction

Semantics, focus, contrast, zoom, motion, cognition and assistive technology belong in the system.

05

Best solved system first

Reuse mature systems and standards before generating custom code or components.

06

Production is the truth

Prototypes and screenshots are inputs; real implementation and validation are the completion gate.

AI + agents

Make machine behaviour legible.

The interface should not collapse recommendation, generation, execution and verification into one vague “AI” state.

Suggested → Generated → Inspected → Verified → Executed → Human-approved

These states let people understand what happened, what was actually checked, where uncertainty remains and when an action crossed a meaningful permission boundary.

Inclusive design

One product, many ways to use it.

The standard covers keyboard, assistive technology, touch, pointer, zoom, reduced motion, clear language, adaptation, localization and other applicable access needs.

Interaction

Do not make essential tasks depend on hover, animation, precise gestures or one device class when an equivalent accessible path can exist.

Content

Design for short and long content, errors, missing media, localization, user-authored information and machine-generated text.

Adaptation

Support useful personalization and preference changes without hiding essential meaning or removing user control.

Evidence

Record what was actually checked rather than implying that accessibility or quality was proven by generation alone.

For practitioners

Plain-language guidance is the entry point. Designers, developers and agents can move into contracts, structured data and validation requirements.

Versioning

v0.1 is intentionally changeable.

Future changes should be justified by research, benchmarks, production evidence or community feedback. Material changes record rationale, evidence class, affected users and migration implications.
